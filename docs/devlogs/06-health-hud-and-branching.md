# 06：血量显示与迷宫分岔优化

日期：2026-10-03。版本：v1.0.3。

## 用户反馈

试玩截图出现 HP 9/100 但血条仍满格，同时已经显示 RUN LOST；迷宫体验接近单条长通道。
本次作为实际试玩缺陷与玩法质量改进留痕，不把自动化记录冒充用户手测。

## 根因

1. 血条创建为纯色 Image，没有 Sprite；设置 Filled 和 fillAmount 不会生成预期的填充裁切，导致数值变化而画面满条。
2. Health 已将血量扣到 0 并触发死亡，但 GameDirector 在 Lost 阶段直接退出 Update，没有刷新最后一次扣血后的 HUD。
3. 原深度优先回溯生成偏长走廊，候选筛选又首先追求目标路线长度。旧第一关全图仅 4 个路口，主路线只有 1 个选择点，第一次选择索引 19，即第 20 格。
4. 小地图把“相邻格尚未探索”的路口画成边界线，真实存在的支路也不容易从地图上看出。

## 修复与取舍

- GameHud 通过 RectTransform.anchorMax 调整实体宽度，0 血时宽度为 0。
- 订阅 Health.Changed，同一帧响应扣血、恢复和重试；销毁时退订，结算前同步顶栏。
- 生成算法改为 Growing Tree：65% 继续最新格子的走廊，35% 从其他活动格扩展，减少深度优先的长通道倾向。
- 每关使用 96 到 512 个确定性候选，先比较分岔质量，再比较路线长度与评分。当前十关满足：路口密度至少 18%，最多走 3 格就遇到选择，连续没有选择的路段不超过 8 格。
- 调低原来过长的目标主路线，为更多支路留空间；实际主路线仍从 17 格逐关增加到 50 格。
- 小地图用金色短标记表示已知格子的未探索出口，不把整个邻格计为已探索，也不提前显示完整解。

新版第一关：10 个三岔及以上路口、主路线 8 个选择点、第 3 格出现第一次选择；第十关 40 个路口、20 个主路线选择点。全部关卡明细见 `../02_CAMPAIGN_AND_BALANCE.md`。

## 自动测试

修复前新增两项 HUD 回归均失败；血条预期 0.35 实测全宽，死亡时文字仍是 9/100。旧版分岔门槛测试也失败。
原始证据位于 `../test-results/v1.0.3/hud-before.xml` 与 `branches-before.xml`。

修复后：EditMode 10/10，PlayMode 16/16 PASS。

- 扣 65 血后实际血条宽度为 35%，治疗 15 后为 50%，重试恢复 100%。
- 死亡事件同一帧出现结果界面时，显示 0/100、宽度为 0。
- 检查小地图纹理中出口短标记可见，但邻格中心仍未知，探索数不增加。
- 检查十关岔路门槛、不同布局、主路线递增、所有格子连通、通道双向一致。
- 保留上一轮十关 CharacterController 实际路线与全部开放岔路移动、平台防掉落回归。

测试适配：旧地图探索测试直接写 transform.position，可能与 CharacterController 内部位置不同步；改为使用上一版引入的 Teleport API 并同步物理变换，不修改断言来掩盖失败。

## 实际运行与交付

Windows 正式包连续走过前六格后，分别模拟损失 65 血和致命伤害。实际日志为 `HP 35 / 100 ratio=0.35 phase=Playing` 与 `HP 0 / 100 ratio=0 phase=Lost`，截图确认粉色条缩短、死亡后清空。
本次三平台构建成功，均 0 错误 / 0 警告，三个发布附件 SHA-256 校验通过。截图、原始 Player 日志、测试 XML 及构建指标摘要均已保存在项目 docs 内。
操作步骤与截图见 `../08_V1_0_3_HUD_AND_BRANCHES.md`。
自动测试不能证明十关战斗平衡或主观手感都已满意，WebGL 交互、Android 真机和用户新版试玩仍需复测。
